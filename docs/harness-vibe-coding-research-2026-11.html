04七个方向性转折

按重要性排序，每条附最关键证据。

SHIFT 01

从「堆 harness」到「删 harness」

每层脚手架都编码了「模型做不到 X」的假设；模型变强，假设迅速过时。

Opus 4.5 让 context reset 整个消失；Opus 4.7 被称为 "a harness release"。[2][19]
SHIFT 02

Harness 比模型更决定分数

同模型换 scaffold 可摆动 10–15 分，极端案例 58% ↔ 79.8%。

LangChain 模型固定，Terminal-Bench 52.8% → 66.5%。[15][18][27]
SHIFT 03

单 agent + Skills 折叠 subagents

递进披露消灭了拆分的原始理由；system prompt 可缩减 80%+。

仅在「上下文膨胀 / 并行可丢弃 / 工具冲突」三条件下保留 subagent。[10][9][8]
SHIFT 04

工具面收缩与 bash gravity

描述写薄了，模型都会漏回 bash；工具越多，选择越差。

Vercel 删 80% 工具后成功率反升到 100%。[15][3]
SHIFT 05

完成判定交给系统

"Done" 必须是系统决策，不是模型声明。

只读 exit code；红了原样回灌失败输出；带固定重试预算。[16][17]
SHIFT 06

安全与自主工厂叙事受挫

45% AI 代码未过安全测试；无人监管软件工厂 3–4 个月后归档。

瓶颈不是 harness，是模型；答案是人类检查点。[37][19][38]
SHIFT 07

标准化与商业整合

Skills / AGENTS.md / MCP 全部走向基金会治理。

约 100 万 skills、2.8 亿安装；60,000+ 项目用 AGENTS.md。[8][39]
COUNTER

Simon Willison：越用 coding agent，越确信它让软件工程更难。

需要非凡纪律与知识，才能兑现其潜力。[38]

06构建路线：七步

按顺序建，不要跳层。先约束 → 再反馈 → 最后质量门。[36]

STEP 0

先写 eval[40]

真实轨迹做 error analysis，先于自动化 eval。

STEP 1

最小内核[25]

loop + 5 个工具 + bash；输出全部有界。

STEP 2

工具契约[3][16]

五段式描述；负向边界说两遍。

STEP 3

上下文工程[5]

稳定前缀、append-only、先 recall 后 precision。

STEP 4

验证契约[16][17]

exit code 判定；原始失败回灌；诚实规则。

STEP 5

编排[10]

先单 loop；subagent 只在三条件下使用。

STEP 6

安全基线[13]

OS 沙箱、默认禁网、保护路径只读。

STEP 7

迭代纪律[2][19]

一次一变量；模型升级后 re-baseline。

07编排决策：还要不要 subagent？

条件结论
单循环被上下文膨胀拖垮用 subagent
需要并行且可丢弃的干净窗口用 subagent
工具选择或指令冲突用 subagent
以上都不成立保持单循环 + Skills

两条硬规则[11]

按上下文切，不按问题类型切。 按问题类型会制造「传话游戏」，每次交接都掉保真度。[10]

成本： Agent Teams ≈ 3–4x tokens（每个 teammate 是完整 session）。[9]

不适合： 顺序任务、同文件编辑、强依赖任务。[10]

08对本仓库的直接启示

对象建议
spec-coding-skill方向正确，但防 spec 膨胀：把 spec 当活工件，接受实现中的学习回写。[28][30]
leo-team-plugin6 角色编排必须先有 eval 证明单 agent + skills 不够；默认答案应是「折叠」。[10]
验证层补验证契约 + 诚实规则——当前最强单项质量杠杆。[16][17]
hooks继续用 hooks 做确定性验证（lint/test 回灌），不要用 prompt 让模型「记得跑测试」。[9]
skills用足递进披露：索引进系统提示，body 按需加载，别把流程塞进 CLAUDE.md。[8][9]
