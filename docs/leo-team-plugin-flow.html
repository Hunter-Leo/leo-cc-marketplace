N0

Precheck · 值不值得组队

mission=planning

在花掉任何团队成本之前做成本判断。不建分支、不写业务代码、不 spawn 队友。

› › › › › ›
并行分支：XS/S 或 T1 不成立 → 退回 spec-coding-skill，不创建 flow.json。用户坚持组队 → 写 D-NNN 覆盖记录，最小队 executor + reviewer，science 全关。
硬编码入口条件：必须同时满足 T1 ∧ (T2 ∨ T3 ∨ T4)，否则不进入 team 流程。
人工 机械
N1

Phase A · 需求构建

mission=planning

把用户需求变成可执行、可验证、可交接的磁盘文件。仍然不建分支、不写业务代码。

› › › › › ›
让位规则：槽位不足时按 P0 researcher → P1 explorer → P2 architect 让位；让位 ≠ 取消，PM 必须写「谁让位、第二批何时启动」进 decisions.md。
BLOCKED 语义：输入缺失 → 队友立刻 BLOCKED，PM 不得猜着补写。
人工 机械
N2

Hard Gate · 唯一一次总授权

mission=gate

在创建分支、组队、写代码之前，拿到用户对本轮计划的明确授权。这是整个流程最硬的一道门。

› › › › ›
三不原则：不自动确认、不超时放行、不代答。用户不确认就永远停在 gate。
确认作废：plan / tasks / decisions / 分支名 / science gate 任一实质变化 → 旧确认失效，必须重提重确认。
合法回退：禁止 gate → planning；必须 transition --to blocked 再 flow.sh recover。
人工 机械
N3

Formation · 切单元与组队

mission=gate → executing

把 tasks.md 变成可机械调度的 team-plan：每个单元一个 owner、一个写集、一条验收命令。

› › › › › › ›
硬规则：共享可变文件（index / router / types / schema / migration）只能有一个 owner，其他单元通过接口消费。
并行幻觉：owned_files 不相交只是「允许调度」的前提，不是「可以同时写」的许可；全局永远只有一个 claim。
人工 机械
N4

Execution · 调度与执行

mission=executing

PM 只做编排、验收、记录。实现单元永远串行；并行只发生在只读分析 vs 写入之间。

› › › › › › › ›
checkpoint：每 3 个单元一次；executor 先 commit，reviewer 绑定固定 commit 审 —— 禁止审还在变动的工作区。
PreCompact：executing / reviewing 期间 checkpoint 必须 ≤30 分钟，否则 hook 拦截压缩。
PM 等待期间禁令：不分析、不代写、不代判、不抢先推进、不重复催问、不开第二个同名角色。
人工 机械
N5

Round Review · 轮次收口

mission=reviewing

用独立上下文判断本轮能否进 N6；不能就在同 session 开 Round N+1。

› › › › ›
增量原则：mission 保持 reviewing，禁止 reviewing → executing；新任务 ID 用 R<N>-U<k> 并写 supersedes。
易漏一步：修复单元复审 PASS 后，PM 必须把对应 finding 的 Status 改为 fixed / accepted 并附证据，否则 check-team-complete 会一直判为未闭合。
人工 机械
N6

Verification · 集成验收

mission=reviewing → verified

把「审过了」推进到「可审计地合并并验收」。三态必须按序到达，禁止合并声明。

› › › ›
负向不变量：删除类 AC 必须验证 symbol 消失、入口不可达、契约同步、无静默回退、消费者已迁移 —— 只证明新功能可用不算通过。
反作弊：禁止删 flow.json、改 mission、跳过 hook、伪造 verified；脚本没有 abandon 白名单。
人工 机械
